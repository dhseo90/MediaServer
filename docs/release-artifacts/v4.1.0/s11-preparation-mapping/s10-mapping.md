## 행 판독 규칙

등록 열은 inventory 사전 정의 또는 중앙/spec 명시 정의다. 중앙 첫 동일ID 출현은 결과/회귀 인용일 수도 있으므로 중앙 첫 이름 검색 결과만으로 사전등록 증거를 승격하지 않는다. '본문 연결'도 전체 요구의 형식적 coverage 증명이 아니다. 공통 Check/Expect/조건식의 여러 label/매개변수는 독립 구현으로 세지 않는다. 명령은 **작성된 호출 경로이며 이번에 실행하지 않았다**. 표의 …/는 scripts/internal/ 축약이다. 링크 label의 숫자는 원문 행 번호다. shell 링크/의존성의 실제 빌드 성공은 이번 감사에서 재검증하지 않았다. ## 역방향 대조·중복·미확인

코드 label 후보는 scripts/internal의 녹화 C++/JS/H 파일76개에서 추출한 뒤 assertion 주변을 읽었다. 부분문자열 PM/FR를 M/R로 잘못 포착한 후보는 제외했다. S10-C330~333/C501~508와 F03~10은 동적/매개변수 label이므로 literal 부재를 누락으로 세지 않았다. code-only처럼 보인 SB07은 inventory414행 prose와 중앙6행 정의가 있어 미등록으로 판정하지 않았다. 등록 범위에서 확인한 새로운 확정 code-only 누락은 없음이나, 임의의 비S10 label 전체를 S10으로 귀속시키는 완전성까지 주장하지 않는다.

동일 ID 다중 assertion 및 다른 ID 공통 assertion 예: SB05 6옵션, SB07 6sidecar, C323-A/B/C, C330~333 공통복구, C501~508 공통Measure, F03~10 공통Child/IndependentOracle, D3A01/02, D3B03/04·10/11, D02-04/10. ID 하나=assertion 하나라는 총계 계산은 금지한다.

33행 후속 대조: T01~08은 실제 writer/input/locator/range/selector의 공유 상위 기준이며 독립 신규 검사 부재로 보지 않는다. T09는 managed_writer301~314의 실제 writer/decode를 사용하는 관측값 fast/drift 변형 검사가 이미 있다. 이를 P06 순수 모델뿐이라고 설명한 이전 판단은 정정한다. 남는 누락은 실제 source 입력 pacing/속도 변화와 clock drift를 함께 주입하는 입력→관측→writer 통합이다. C336/E19/D02-09/D3B15/REG는 기존 회귀집합, REG-isolation은 후속 ISO01~10 정의·harness와 결박된다. spec D08은 실제 browser 사용자 제외이며 VM/API 대체 불가다. D3D10은 seed 종료 뒤 첫 서버 시작복구이지 두 번째 서버 기동은 아니다.

실제 수행: rg/rg --files, sed -n, git 기준 조회, Node fs.readFileSync 기반 ID/행/runner 호출 수집. 대표 재현 읽기 명령: rg -n 'S10-' docs/project-feature-test-inventory.md; rg -n 'S10-REG-' docs/release-test-records.md; rg -l 'src/recording/recording_read_service.cpp' scripts --glob '*.sh'; sed -n '29,40p' scripts/internal/recording_foundation_suite.mjs. 성공한 읽기 수집 exit0. 일부 oversized 도구 출력/JSON 수집이 잘려 소범위 읽기로 보완했으며 제품 검증 실패/RED가 아니다. 없는 후보 파일 경로 rg/ls exit1/2는 조사 후보 부재로 기록하고 실제 존재하는 harness 경로로 대조했다.

수정은 이 문서뿐이다. 최초 작성한 중복 JSON은 메인 요청으로 제거했다. 제품·테스트·문서 gate·최종 suite 실행 없음. 임시 미디어/서버/port/계정/credential 생성 없음, cleanup 대상 없음. 커밋/푸시 없음. token start/end/consumed는 이 하위 작업의 신뢰 가능한 집계 제공이 없어 미집계; elapsed도 실행 검증 시간으로 보고하지 않는다. 부모의 미커밋 plan 변경은 보존한다. 이후 매핑 보완/준비 수정과 승인된 실행은 별도 단계이며 이 문서로 실행 승인을 확장하지 않는다.
