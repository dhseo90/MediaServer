# Media Server v4.2.0

v4.2.0은 기존 녹화 카탈로그와 분석 관측을 사용하는 구조화 검색을 추가합니다.
소스 버전과 공개 목표는 v4.2.0이며, 태그·GitHub Release 공개 완료를 뜻하지 않습니다.
기록된 공개 관측은 [릴리즈 정책](release-policy.md#소스와-기록된-공개-상태)에 유지합니다.

## 추가 기능

- 카메라·시간·객체·track·event·zone·rule·behaviour 필터와 별도 검색 read model.
- 불변 snapshot에 묶인 안정 페이지, 질의·사용자·scope 검증과 만료 처리.
- 동일 원본의 입증된 범위에서 이벤트 영상 우선 선택, partial 밖 원본 보존.
- 현재 원본/파생 파일의 근거로 계산하는 검색 시점 재생. 미지원 파일은 명시적 이동 불가 안내.
- 기존 Ops 이벤트 화면의 구조화 검색 폼·결과·다음 페이지·재생 연결.

사용법은 [UI 가이드](ui-guide.md#녹화-구조화-검색-v420),
요청·응답은 [설정/API 참조](config-reference.md#구조화-녹화-검색-api-v420)를 따릅니다.
기존 timeline/media API, 원본 녹화 저장·시간·ID·보존·복구 계약은 유지합니다.
검색 projection은 원본을 수정하지 않고 기존 reader에서 재구축하며 새 저장 형식 migration을 요구하지 않습니다.

## 한계와 검증 상태

자연어·벡터 검색, 새 행동 추론, VLM 판단, 자동 후속 파일 재생은 포함하지 않습니다.
촬영 시각을 알 수 없는 자료는 시간 미확인으로 구분합니다. 정확한 위치 이동은 파일의
시간 대응을 입증할 수 있는 경우에 제공하며 임의 컨테이너·codec 지원을 보장하지 않습니다.
read model·snapshot은 명시한 논리 메모리 한도를 적용하며 RSS나 기존 catalog 누적 비용의 상한은 아닙니다.

## 검증과 공개 상태

초기 개발 범위에서는 릴리즈용 검사를 제외했습니다. 이후 별도 승인으로 실행한 결과는
[종료 기록과 원본 보존 위치](history/README.md#v420-개발과-최종-검증)에 구분해 연결합니다.
이번 문서·증거 정리는 새 HEAD에서 제품 검사를 다시 실행한 결과가 아닙니다.

- canonical 실행 `ce163652`에서 빌드·기능 gate 36개·일반30분·기본 UI exact424 적격 판정·일반120분·cleanup이 통과했습니다. 외부 TURN 등 원래 비대상은 그대로입니다.
- 녹화 UI 31개 action은 두 실행의 관측·캡처를 구분해 검토했습니다. 검색 UI는 `debfe085`와 보존 diff에서 38개 action/30개 기능 ID를 실행했고, 106개 캡처의 별도 시각·권한·접근성 검토를 연결했습니다. 서로 다른 단위를 합산하지 않으며 seek 완료를 표시 frame의 정확성 입증으로 확대하지 않습니다.
- 녹화120분은 `b6ad8df65d1e194504c7a650bf3208e72d05e15d`에서 기능·저장·복제·재기동·재활성화·cleanup이 통과했습니다. 최초 예산 실패와 후속 PASS는 별도 원본으로 보존합니다.
- Linux는 격리 Debian sid ARM64, GCC 16.2.0·CMake 4.3.4·Node 24.21.0·GStreamer 1.28.7 구성에서 제품 빌드/링크, auth auto 최초 setup, 합성 H.264의 RTSP/TCP 디코드·EOS와 종료를 확인했습니다. 실행 source는 `6a30de5c`와 보존 portability diff이며 코드 반영은 `263b162c`입니다. 다른 배포판·아키텍처, Linux 실제 UI·WebRTC·ONNX·녹화/검색 장기 부하는 미검증입니다.

행동 근거 부족은 정상 불일치와 구분하고, 재생 UI는 해당 선택의 실제 seek 완료를 확인합니다.
기존 저장·시간·권한·snapshot·현재 media 보호 계약은 유지합니다.
개발 회귀와 위 실행은 각각의 source·환경·제외 범위에서 유효하며 과거 FAIL·미실행을 덮어쓰지 않습니다.

녹화120분 원출력의 `resourceTrendPass=false`는 유지합니다. 누적 이력 RAM·대규모 동시 부하와
무조건적 자원 안정성을 보증하지 않으며 [기존 메모리 운영 한계](development-backlog.md#녹화-누적-이력의-메모리-운영-한계)는 미해결입니다.
F/R/copy 예산은 고정 입력과 제품 가변 파일·복제본의 논리 파일 바이트 보호이며 RSS 한도가 아닙니다.
정상 관측 약5초·native 복구 감시 약100ms의 주기 사이 모든 순간을 강제 제한한 것은 아닙니다.
약148ms의 별도 검색 준비 잠금 대기 관측도 모든 요청 지연이나 성능 합격선이 아닙니다.
