# v3.9.0 Review2 Steps 19-20 구현 계획

대상 독자는 v3.9.0 release correctness gate와 feature implementation evidence를 유지보수하는 개발자입니다. Lifecycle: historical REVIEW2 19·20 실행 계획이며, 984행 closure의 current claim은 `V390-REVIEW4-52`/`V390-REVIEW4-53`에 의해 superseded되었습니다. 아래 당시 절차와 수치는 과거 사실로 보존하지만 current semantic completion evidence로 사용하지 않습니다. 정책 source-of-truth는 `AGENTS.md`, 상태 source-of-truth는 `docs/development-backlog.md`, 테스트 항목 source-of-truth는 `docs/release-test-records.md`입니다.

## 범위와 불변 조건

- Step 19: current entry baseline gate를 구조화된 진행 상태 표 검증으로 교체합니다.
- Step 20: 984개 feature implementation manifest를 reviewer 승인형 semantic evidence로 교체합니다.
- Event POST, WebRTC DataChannel, SSE/WS metadata, RTSP/WebRTC media path, Auth/Role/Scope, SourceRegistry/PublishedView, Rule/Profile payload는 변경하지 않습니다.
- 30분, 120분, UI 풀테스트, published metadata, release action은 실행하지 않습니다.

## Step 19 RED-GREEN-REFACTOR

1. `v390_entry_baseline_steps.json`에 Step ID, 제목, priority, current status, historical boundary를 단일 expected-state fixture로 고정합니다.
2. 독립 contract에서 current backlog positive, 과거 exact 문구, 누락 Step, 중복 Step negative를 먼저 실행해 RED를 확인합니다.
3. Markdown 진행 상태 표 parser/validator를 공용 library로 구현하고 entry verifier가 이를 사용하게 합니다.
4. actual acceptance command list가 같은 `verify-v390-entry-baseline`을 호출하는지 검증합니다.
5. roadmap/evidence/test record를 실제 구현·검증 결과로 갱신하고 관련 안정화 gate와 `git diff --check`를 통과시킵니다.

## Step 20 RED-GREEN-REFACTOR

1. 기존 substring owner와 일괄 `closed-with-evidence`를 거부하는 negative contract를 먼저 추가합니다.
2. 각 manifest row에 reviewed semantic evidence(`handler`, `route`, `controlSelector`, `actionHandler`, `stateOracle`, `verifierAssertion`)와 관계 정보를 저장합니다.
3. generator는 기존 reviewer 승인 evidence를 보존하며, 자동으로 semantic closed 상태를 부여하지 않습니다.
4. validator는 exact symbol/route/control/assertion과 관계를 검증하고 generic/shared substring, 같은 파일의 무관 anchor, ID-only verifier를 거부합니다.
5. 984행을 명시적으로 review한 manifest로 이관한 뒤 negative fixture, inventory, acceptance companion gate, docs/diff를 검증합니다.

## 단계 종료 기준

- 각 단계의 관련 test item이 실행 전에 `docs/release-test-records.md`에 등록되어 있습니다.
- 최초 실패와 수정 후 재검증 결과를 모두 기록합니다.
- roadmap에 파일·함수·fixture·verifier 단위 구현 위치와 미실행 경계를 남깁니다.
- 각 단계는 별도 커밋하며 push는 수행하지 않습니다.
