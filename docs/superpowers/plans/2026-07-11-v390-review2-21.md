# v3.9.0 Review2 Step 21 Analysis Registry Durable Write 구현 계획

대상 독자는 Analysis Registry 저장 경계와 HTTP mutation route를 유지보수하는 개발자입니다.
Lifecycle은 `V390-REVIEW2-21` 개발과 안정화 종료까지이며, 권한·테스트·보고 정책은
`AGENTS.md`, 상태는 `docs/development-backlog.md`, 테스트 항목과 결과는
`docs/project-feature-test-inventory.md`와 `docs/release-test-records.md`가 우선합니다.

## 목표와 경계

- profile, rule, VA rule, VLM profile의 create/update/delete는 저장 후보를 atomic
  temp-write/flush/rename으로 durable commit한 뒤에만 메모리에 publish합니다.
- parent/open/short-write/flush/rename 실패는 typed persistence error로 호출자에게 전달하고
  HTTP 500을 반환합니다.
- 실패한 mutation은 같은 process GET, registry file bytes, 재시작 GET을 모두 변경하지 않으며
  임시 파일을 남기지 않습니다.
- validation 400, not-found 404, Auth/Role/Scope, payload schema, Event/WebRTC/SSE/WS/media path는
  현재 계약을 유지합니다.

## Superpowers 실행 순서

1. inventory와 release test 정의, fixture case를 제품 테스트 전에 등록합니다.
2. 신규 verifier를 구현하고 제품 코드 변경 전 RED를 보존합니다.
3. `AnalysisDocumentRegistry` mutation을 persist-before-publish로 전환하고 typed write result를
   HTTP status mapping에 연결합니다.
4. 신규 actual HTTP verifier를 처음부터 재실행한 뒤 build와 analysis/auth/inventory/docs
   companion gate, `git diff --check`를 실행합니다.
5. roadmap/evidence에 최초 실패, 수정, 최종 결과, 미실행 테스트, cleanup을 기록합니다.
