# v1.1.0 Roadmap

이 문서는 v1.0.0 source-only baseline 이후 v1.1.0에서 개발할 목표와
제품 경계를 고정합니다. 다른 문서에서 v1.1.0 범위가 모호할 때는
이 문서의 live-only 기준을 우선합니다.

v1.1.0의 이름은 다음 방향으로 둡니다.

```text
Live Operations / ONVIF Onboarding / Live VA Events
```

핵심 판단 기준:

- MediaServer는 live media relay와 live video analytics event engine입니다.
- v1.1.0은 VMS, NVR, 장기 녹화, playback/search 제품으로 확장하지 않습니다.
- ONVIF는 카메라를 찾고 live stream을 연결하기 위한 onboarding 수단부터 다룹니다.
- VA는 더 많은 녹화 기능이 아니라 live event 품질, 운영 visibility, 현장 tuning을 고도화합니다.

## 1. Product Boundary

### 포함 범위

- live source discovery/import
- ONVIF-assisted live source onboarding
- live RTSP/WebRTC relay
- live VA overlay/metadata/event
- live event delivery through Event POST, WebRTC DataChannel, SSE, WebSocket
- 운영자용 source health, reconnect, stale/offline 상태 요약
- client viewer용 sanitized live/dashboard 상태
- 짧은 event context와 metadata 중심의 recent state

### 제외 범위

- 장기 녹화, MP4 muxing, video archive, playback timeline, 영상 검색
- NVR/VMS style recording management, ONVIF Profile G recording/replay scope
- evidence 원본 삭제/장기 보관 UI, 저장 영상 기반 분석 workflow
- ONVIF conformant server, recorder, replay service
- recorded evidence 중심의 외부 integration contract

기존 EventRecord, snapshot, clip frame bundle hook은 v1.1.0의 중심 제품 메시지가
아닙니다. 유지하더라도 default-off 운영 보조 또는 debug/developer 기능으로 다루고,
새 기능은 live event 처리와 live 상태 판단을 우선합니다.

v1.1.0 기능 요구사항이 위 제외 범위를 필요로 하면 해당 요구사항은
v1.1.0 scope에서 분리하고 별도 phase로 기록합니다.

### 1차 문서 경계 점검

v1.1.0-alpha.1의 첫 작업은 문서에서 live-only 경계가 흐려지는 표현을
먼저 분리하는 것입니다.

수정 우선 대상:

- `README.md`, `README.en.md`: 첫 소개와 한눈에 보기에서 EventRecord,
  snapshot, clip evidence가 v1.1.0 중심 기능처럼 보이지 않게 정리
- `docs/development-backlog.md`, `docs/en/README.md`:
  다음 작업을 ONVIF onboarding, live source health, live VA event 품질로 고정
- `docs/config-reference.md`: MP4/VMS/NVR형 recorder를 후속 범위처럼
  읽히게 하는 표현을 v1.1.0 비범위로 정리
- `docs/versioning-policy.md`, `docs/en/README.md`:
  v1.1.0 포함/비포함 범위의 한국어/영어 의미 동기화

유지 가능하지만 제품 메시지에서 보조로 다룰 대상:

- EventRecord JSON Lines 저장과 active/archive 조회
- snapshot media와 clip frame bundle hook
- evidence retention cleanup job
- `/ops/events` 직접/진단 route

위 대상은 live event context, 운영 진단, default-off evidence 보조 기능으로만
설명하고, 장기 녹화/재생/검색/보관 제품처럼 표현하지 않습니다.

### 제품 문구 가드레일

한국어/영어 세부 용어와 비범위 키워드 점검 기준은 이 문서의
`Live-only Glossary`와 `Boundary Keyword Checks` 섹션으로 통합했습니다.

v1.1.0 문서와 UI 문구는 다음 표현을 우선 사용합니다.

- `live source onboarding`
- `ONVIF camera import`
- `live source health`
- `live VA event`
- `runtime metadata`
- `short event evidence`

다음 표현은 v1.1.0 제품 설명, milestone, release note의 중심 문구로
사용하지 않습니다.

- `VMS`
- `NVR`
- `long-term recording`
- `video archive`
- `playback timeline`
- `recorded evidence API`
- `ONVIF Profile G recorder`

기존 구현 설명 때문에 위 표현이 필요하면 반드시 `비범위`, `보류`,
`default-off`, `debug/developer`, `short event evidence` 중 하나의 상태를
같은 문단에서 함께 명시합니다.

## 2. ONVIF Direction

v1.1.0의 ONVIF 목표는 conformant ONVIF device/server를 만드는 것이 아닙니다.
목표는 운영자가 ONVIF camera를 찾아 live stream source로 등록하는 것입니다.

### 1차 목표

- ONVIF discovery 후보 조사
- device information/capabilities 조회
- Media/Media2 profile 조회
- live RTSP stream URI 추출
- 인증이 필요한 camera credential 입력/저장 정책 초안
- 추출한 stream URI를 기존 SourceRegistry source로 등록
- PublishedView와 VA rule 연결 흐름 유지

### 명명

제품 표현은 다음처럼 제한합니다.

- 사용: `ONVIF camera import`, `ONVIF-assisted live source onboarding`
- 사용하지 않음: `ONVIF conformant server`, `ONVIF Profile G recorder`,
  `full ONVIF VMS`

### Profile 판단

- Profile T를 신규 live streaming 연동의 기준 방향으로 둡니다.
- Profile S 장비는 현장 호환성을 위해 best-effort import 대상으로 둡니다.
- Profile M은 live analytics metadata/event export 연구 항목입니다.
- Profile G는 v1.1.0 범위에서 제외합니다.

참고:

- [ONVIF Profile T](https://www.onvif.org/profiles/profile-t/)
- [ONVIF Profile M](https://www.onvif.org/profiles/profile-m/)
- [ONVIF Profile S](https://www.onvif.org/profiles/profile-s/)
- [ONVIF Profile S support end announcement](https://www.onvif.org/?p=8621&post_type=pressrelease)

## 3. v1.1.0 Themes

### T1. Live Source Onboarding

목적:
운영자가 file/RTSP/HTTP/WHEP/WHIP source뿐 아니라 ONVIF camera도
live channel로 빠르게 등록할 수 있게 합니다.

범위:

- `/ops/sources`에서 ONVIF camera 후보 확인
- stream URI import 전 source preview/검증
- SourceRegistry에 live RTSP source로 저장
- source kind와 origin metadata를 구분해 operator가 추적 가능하게 표시
- credential/plaintext secret 노출 금지

비범위:

- camera recording configuration
- edge storage 조회
- replay URL import
- PTZ control 1차 구현

### T2. Live Source Health

목적:
카메라와 source가 늘어나도 운영자가 현재 live 상태를 빠르게 판단할 수 있게 합니다.

범위:

- source reachability 상태
- last frame age
- reconnect count
- stale/offline reason
- codec/profile summary
- client live와 ops dashboard에서 같은 상태 의미 사용
- bulk source health check 초안

비범위:

- 저장 영상 health
- playback gap 분석
- 장기 recording retention 상태

### T3. Live VA Event Quality

목적:
v1.0.0에서 구현된 scenario engine을 실제 현장 운영에 가까운 품질로 다듬습니다.

범위:

- Loitering/ZoneOccupancy threshold baseline 보정
- actual/field-like sample 기반 TrackHealth threshold 수집
- close-object association diagnostic 비교 리포트 고도화
- Scenario timeline/debug UI에 phase entered time, cooldown remaining 추가
- `vaRule` runtime debug를 rule별 실행 상태 확인 중심으로 정리

비범위:

- Re-ID default-on
- ByteTrack, BoT-SORT, Kalman tracker 교체
- 사람 attribute/face/license plate 같은 식별성 높은 분석

### T4. Live Event Delivery Contract

목적:
외부 시스템이 저장 영상이 아니라 실시간 이벤트와 metadata를 안정적으로 소비하게 합니다.

상태:

- `완료`: 2026-05-12 순차 close-out 기준으로 선수 로드맵 5/6을 닫았습니다.
- RC에서는 Event POST/WebRTC/SSE/WS smoke matrix가 유지되는지만 확인합니다.
- OpenAPI/JSON Schema artifact 생성은 RC 잔여 blocker가 아니라 외부 연동 확장 후보입니다.

범위:

- Event POST schema 문서 분리
- WebRTC DataChannel metadata schema 문서 분리
- SSE/WS runtime metadata contract 정리
- metadata filter preset과 subscription command 검증 유지
- live event delivery failure metric 요약
- 기준 schema 식별자 고정:
  `media-server.va.event.v1`,
  `media-server.webrtc.va-metadata.v1`,
  `media-server.va.runtime-metadata.v1`,
  `media-server.va.metadata-control.v1`

비범위:

- recorded evidence API를 주요 integration contract로 승격
- OpenAPI 기반 VMS archive/playback API
- Event POST/WebRTC/SSE/WS payload field 변경

### T5. Multilingual UI and Docs Quality

목적:
한국어/영어 UI와 문서가 v1.1.0의 제품 경계와 같은 의미를 전달하게 합니다.

상태:

- `완료`: 2026-05-12 순차 close-out 기준으로 선수 로드맵 6/6을 닫았습니다.
- 짧은 영문 mirror 문서는 `docs/en/README.md`로 병합했습니다.
- RC 잔여 범위는 영문 UI screenshot/text smoke 유지 여부입니다.

범위:

- 언어 선택 정책과 저장 위치 확인
- `/ops`, `/client`, `/setup`, `/login` 주요 화면의 한글/영문 혼재 점검
- 영문 스크린샷의 한글 잔존 여부 점검
- 한국어/영어 문서의 v1.1.0 용어와 비범위 표현 동기화
- operator/client visible text와 debug/developer text의 번역 범위 구분

비범위:

- 완전한 i18n framework 재구축
- 모든 내부 개발/debug 문자열 번역
- API schema, event payload, enum, machine-readable 값 번역

## 6. Live-only Glossary

이 섹션은 별도 glossary 문서를 대체합니다. v1.1.0 live-only 제품 경계를
설명할 때 사용하는 한국어/영어 용어를 고정합니다. UI/API의
machine-readable enum, event payload, schema field 이름은 번역하지 않습니다.

### Core Terms

| 한국어 표현 | English term | 사용 기준 |
| --- | --- | --- |
| live-only 제품 경계 | live-only product boundary | v1.1.0이 녹화/VMS/NVR로 확장하지 않는다는 최상위 기준 |
| live media relay | live media relay | RTSP/WebRTC live stream 중계 역할 |

### Non-goal Terms

문단에서 `비범위`, `보류`, `default-off`, `debug/developer`,

### Translation Rules

- `ONVIF`, `RTSP`, `WebRTC`, `WHEP`, `WHIP`, `SSE`, `WebSocket`,
  `Event POST`, `DataChannel`, `SourceRegistry`, `PublishedView`,
  `EventRecord`, `vaRule`은 원문 표기를 유지합니다.
- `live`는 저장/재생과 구분해야 하므로 한국어 문서에서도 필요하면 원문을 유지합니다.
- `evidence`는 장기 보관 증거처럼 들릴 수 있으므로 v1.1.0에서는
  `short event evidence` 또는 `짧은 이벤트 증거/맥락 보조`로 씁니다.
- `source health`는 저장 영상 health가 아니라 live source 도달성과
  stale/offline 상태를 뜻합니다.
- `metadata contract`는 API schema 변경 약속이 아니라 기존 contract의 문서화와
  검증 기준 정리를 뜻합니다.
- UI visible text는 operator/client가 이해하기 쉬운 문구를 우선하고,
  machine-readable 값은 번역하지 않습니다.

권장 예시:

- v1.1.0은 ONVIF-assisted live source onboarding을 다룹니다.
- EventRecord/snapshot/clip은 short event evidence 보조 기능입니다.
- Client dashboard는 sanitized live source health만 표시합니다.

비권장 예시:

- v1.1.0은 ONVIF VMS를 제공합니다.
- EventRecord API를 recorded evidence integration contract로 사용합니다.
- `/client` 화면에 RTSP source URL과 raw debug JSON을 표시합니다.
