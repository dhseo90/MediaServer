# v1.3.0 Follow-up Closure

이 문서는 v1.3.0 roadmap 기능 개발이 끝난 뒤 남은 후속 항목을 기능 개발 없이
정리합니다. 목표는 v1.3.0 안에 남은 개발 잔여와 이후 별도 Phase 후보를
분리하는 것입니다.

## 기준

- v1.3.0은 source-only/live-only 경계를 유지합니다.
- Re-ID default-on, 대형 tracker 교체, runtime/model binary bundle 포함은
  v1.3.0 기능 개발 범위가 아닙니다.
- Event POST payload, WebRTC DataChannel, SSE/WS metadata, auth/session contract,
  RTSP/WebRTC media path를 변경하지 않습니다.
- 실제 Re-ID model artifact, 고객/현장 영상, credential, 운영 source URL은 repo,
  기본 release asset, 공유 검증 artifact에 포함하지 않습니다.
- 장시간 soak, `verify-predev`, 실제 외부 camera/field device 검증, push는 명시
  요청 없이는 실행하지 않습니다.

## 후속 항목 판정

| 항목 | 판정 | 처리 | v1.3.0 남은 개발 이슈 |
| --- | --- | --- | --- |
| 실제 Re-ID model field review | 별도 Phase gate | 실제 model artifact를 repo/release에 추가하지 않고, field review 착수 조건을 model card/license/checksum, dataset provenance, privacy review, close-object tracker 비교 evidence로 분리합니다. `compare-close-object-tracker`는 close-object baseline과 `review-required` 경계 확인에만 사용하며 제품 default-on 근거로 쓰지 않습니다. | 없음 |
| field sample 반복 수집 정책 | 별도 field review 입력 정책 | 반복 수집 자동화, scheduler, dataset ingest를 추가하지 않고 history index review 기준만 고정합니다. 각 run은 fixture id, run id, report path, `defaultOnDecision`, `productDefaultOn`, `candidateCount`, `defaultOnReason`, hold/warning count를 보존해야 합니다. | 없음 |
| tracker 교체 후보 조사 | 별도 benchmark 후보 목록 | ByteTrack, OC-SORT, BoT-SORT, DeepSORT 계열을 후보군으로만 분류하고 dependency 도입, tracker 교체, Re-ID default-on은 진행하지 않습니다. 별도 benchmark는 current tracker baseline과 event/schema/media path 무변경 조건을 함께 비교할 때만 유효합니다. | 없음 |

## 실제 Re-ID Model Field Review

2026-05-17 KST 기준 실제 Re-ID model field review는 v1.3.0에서 기능 개발로
착수하지 않습니다. 실제 모델 파일, embedding 저장소, 기본 활성화 config, field
dataset ingest는 모두 이후 별도 Phase에서만 엽니다.

착수 전 필요한 evidence:

- model card 또는 equivalent model provenance
- license, redistribution, runtime dependency 검토
- model checksum과 versioned artifact identity
- field sample provenance와 개인정보/보존 정책
- `compare-close-object-tracker` matrix 또는 동등 benchmark report
- `productDefaultOn=false` 유지 확인

2026-05-17 KST 단일 field-like fixture 재확인에서는
`matrix-default-on-decision=review-required`와 `matrix-product-default-on=False`를
확인했습니다. 이 결과는 field review 착수 조건을 보강하는 evidence이며,
제품 default-on 완료 또는 실제 model 성능 검증이 아닙니다.

이 단계에서 확인하지 않는 것:

- 실제 Re-ID model accuracy
- 실제 customer/field camera dataset 성능
- 제품 default-on 결정
- runtime/model bundle 포함 배포

검증 기준:

```bash
./server.sh compare-close-object-tracker --fixture-matrix --fixture-ids field-new-york-driving --history-dir /private/tmp/media_server_v130_followup_model_field_review
git diff --check
```

## Field Sample 반복 수집 정책

field sample 반복 수집은 v1.3.0에서 자동화 기능으로 구현하지 않습니다. 대신
field/model review가 열릴 때 같은 형식으로 evidence를 쌓도록 history
index review 기준을 고정합니다.

정책:

- 같은 fixture 또는 field sample family는 같은 `--history-dir` 아래 누적합니다.
- 각 run은 command, fixture id, quality preset, summary/report path를 남깁니다.
- history index는 `defaultOnDecision`, `productDefaultOn`, `candidateCount`,
  `defaultOnReason`, hold/warning count를 함께 보존합니다.
- `productDefaultOn`은 field review가 끝나기 전까지 `False`입니다.
- `hold`나 `warning`이 하나라도 있으면 제품 default-on 검토를 중단하고
  `review-required` 또는 `not-promoted`로 남깁니다.
- customer/field 영상은 별도 승인과 보존 정책 없이는 repo, release asset,
  공유 artifact에 남기지 않습니다.

이 단계에서 확인하지 않는 것:

- 반복 수집 scheduler
- field dataset upload/import pipeline
- 장시간/상시 camera sampling
- 고객 영상 보존/삭제 자동화

검증 기준:

```bash
./server.sh compare-close-object-tracker --fixture-matrix --fixture-ids tracking-event --history-dir /private/tmp/media_server_v130_followup_field_sample_policy
history index review
git diff --check
```

## Tracker 교체 후보 조사

tracker 교체 후보 조사는 v1.3.0에서 구현하지 않습니다. 현재 제품 tracker는
direction-based/lightweight tracker이며, 후보군은 별도 benchmark를 열 때
비교 대상으로만 사용합니다.

후보군:

| 후보 | 검토 이유 | v1.3.0 판정 |
| --- | --- | --- |
| ByteTrack | low-confidence detection까지 association 후보로 다루는 tracking-by-detection baseline | 후보만 기록. dependency/구현 도입 없음 |
| OC-SORT | SORT 계열의 motion/observation 중심 대안 | 후보만 기록. current tracker baseline 대체 없음 |
| BoT-SORT | motion, appearance, camera motion compensation 조합 후보 | Re-ID/appearance/privacy 부담이 있어 별도 threat model 전까지 도입 없음 |
| DeepSORT 계열 | appearance metric 기반 ID continuity 후보 | Re-ID model/privacy 검토 전까지 제품 default-on 후보 아님 |

별도 benchmark가 열릴 때 필요한 비교 조건:

- current lightweight tracker와 후보 tracker를 같은 fixture/input으로 비교
- Event POST/WebRTC DataChannel/SSE/WS metadata schema 동일성 확인
- RTSP/WebRTC media path와 pipeline blocking 정책 동일성 확인
- track fragmentation, overlap fragmentation, tracker association risk 비교
- CPU/RSS/latency budget과 queue backpressure 영향 확인
- Re-ID/appearance material이 외부 metadata/debug payload에 노출되지 않는지 확인
- 고객/현장 영상 없이 synthetic 또는 승인된 redacted field sample만 사용

이 단계에서 확인하지 않는 것:

- ByteTrack/OC-SORT/BoT-SORT/DeepSORT 구현
- 새 C++ dependency 또는 model bundle 추가
- 실제 별도 benchmark 실행
- tracker default 교체 결정

검증 기준:

```bash
별도 benchmark: 실행하지 않음, 별도 Phase gate
git diff --check
```

## Model/Runtime Bundle 정책 검토

v1.3.0 follow-up closure에서도 기본 release는 source-only입니다. Re-ID model,
YOLO model, ONNX Runtime package, FFmpeg/GStreamer runtime, x264/x265, GPL-risk
plugin은 기본 release asset이나 repo tracked artifact에 포함하지 않습니다.

runtime/model 포함 bundle을 별도 Phase에서 검토하려면 다음이 먼저 필요합니다.

- model/runtime license와 redistribution 조건
- upstream source offer 또는 license text/attribution 필요 여부
- model checksum, provenance, versioned artifact identity
- bundle 안의 customer media, evidence, auth store, log, credential 비포함 확인
- container/offline/binary 후보별 `verify-bundle-policy` 결과
- source-only release note에서 binary/runtime/model 미포함 경계 유지

이 단계에서 확인하지 않는 것:

- runtime/model 포함 bundle 생성
- container image build/push
- offline installer 제작
- GitHub Release asset 업로드

검증 기준:

```bash
./server.sh verify-bundle-policy --output /tmp/media_server_v130_followup_bundle_policy.md --json-output /tmp/media_server_v130_followup_bundle_policy.json
git diff --check
```

## Re-ID Privacy Threat Model

Re-ID/appearance 기능은 기본 비활성이며, v1.3.0 follow-up closure에서 privacy
threat model만 보강합니다. Re-ID default-on, embedding 저장소, model artifact
bundle, field dataset ingest는 열지 않습니다.

identity material로 취급하는 값:

- embedding vector와 embedding quality
- bbox crop 또는 crop에서 생성된 intermediate tensor
- Re-ID model path, model checksum, model artifact identity
- track-linked appearance profile
- field sample provenance, raw frame, camera/source locator

위협과 대응:

| 위협 | 대응 |
| --- | --- |
| 외부 metadata payload로 identity material 노출 | WebRTC/SSE/WS/Event/debug JSON에 embedding/crop/model path를 직렬화하지 않음 |
| client/viewer 화면의 source/debug/raw 정보 노출 | client/viewer에는 source URL, raw JSON, BBox diagnostics, rule/profile editor, identity material을 노출하지 않음 |
| field sample 또는 screenshot artifact의 개인정보 잔존 | redaction/privacy review 전 공유 artifact에 올리지 않음 |
| runtime/model bundle에 Re-ID model 포함 | 기본 release asset에서 제외하고 별도 bundle policy review로만 처리 |
| 장시간/상시 수집으로 retention scope 확대 | v1.3.0에서는 scheduler, dataset ingest, customer media retention을 구현하지 않음 |

검증 기준:

```bash
./server.sh verify-reid-advanced-tracking
docs/privacy review
git diff --check
```

## 추가 후속 항목 점검

development backlog의 v1.3.0 종료 판정과 이 문서의 후속 항목을 함께 확인한
결과, 2026-05-17 KST 기준 v1.3.0 안에서 추가 기능 개발로 처리할 후속 이슈는
남기지 않습니다.

추가로 확인한 경계:

- Runtime operations, source health incident, audit trail, release/visual baseline
  automation은 각 카테고리의 종료 판정과 검증 기준을 유지합니다.
- ONVIF field smoke의 실제 device endpoint 성공은 field gate report에만 남기며
  v1.3.0 개발 완료 근거로 승격하지 않습니다.
- tag, push, GitHub Release, accepted visual baseline 채택은 release 운영 gate이며
  이 closure의 기능 개발 범위에서는 수행하지 않습니다. v1.3.0 GitHub Release는
  별도 release publish 단계에서 완료된 현재 release 상태로 봅니다.
- 장시간 `verify-predev` 또는 runtime console longrun은 사용자 명시 요청이
  없으므로 실행하지 않습니다.
- 이후 기능 개발 후보는 이 문서에 별도 Phase gate로 남기되, v1.3.0 잔여로
  보지 않습니다.

## 결론

- 로드맵 내 개발 가능한 후속 이슈: 없음.
- 남은 항목은 별도 Phase gate 또는 release/field/manual approval gate입니다.
- Re-ID default-on, tracker 교체, runtime/model bundle 포함, field sample
  scheduler, dataset ingest는 이 closure에서 수행하지 않았습니다.
- tag/push/GitHub Release는 기능 개발 closure 범위가 아니라 별도 release 운영
  gate입니다.
- Re-ID 관련 history/benchmark 판단은 `productDefaultOn=False` 경계를 유지합니다.
- 미확인 항목을 통과로 쓰지 않습니다.
