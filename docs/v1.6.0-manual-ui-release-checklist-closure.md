# v1.6.0 Manual UI Release Checklist Closure

이 문서는 V160-P1-04 `Manual UI release checklist closure`의 기준입니다.
목표는 실제 수동 UI 검수를 수행했다고 기록하는 것이 아니라, v1.6.0 현재 제품
화면 기준으로 수동 검수 템플릿과 evidence 경계를 닫는 것입니다.

## 범위

- `/setup`, `/login`, `/password/change`, `/ops/home`, `/ops/dashboard`,
  `/ops/sources`, `/ops/rules`, `/ops/users`, `/ops/events`, `/client/live`,
  `/client/dashboard`, `/client/request-access`를 수동 검수 대상 화면으로 유지합니다.
- `/lab`, `/lab/rules`, `/lab/import`, `/webrtc/test`는 제품 UI로 되살리지 않고 닫힌
  route 상태를 확인 대상으로만 둡니다.
- Client 화면은 Live/Dashboard primary nav만 허용하며 Ops/Lab primary navigation,
  source URL, Developer URL, raw JSON, debug counter, BBox diagnostics, rule/profile
  editor를 노출하지 않습니다.
- Client 화면은 model/source/auth material과 rule/profile editor를 노출하지
  않습니다.
- screenshot과 수동 검수 결과는 실제 실행한 artifact/link만 기록합니다.
- 자동 smoke, raw JSON 확인, screenshot 생성만으로 수동 클릭 검수를 완료했다고 쓰지
  않습니다.

## Result Template 필수 기록

- `확인됨`: 실제 브라우저에서 열고 클릭한 화면, 계정/권한, viewport, 기대/실제 결과
- `미확인`: 열지 않은 화면, 실행하지 않은 장시간 테스트, 실장비/외부 네트워크,
  GitHub Actions/link 미확인
- `건너뜀`: destructive action, fixture 미준비 action, 사용자 승인 없는 push/tag/release
- `비노출 확인`: client/viewer surface에서 source/debug/raw/model/auth material 비노출
- `자동 검증`: `verify-ops-client-ui --screenshots`, `verify-rule-ui`,
  `verify-auth-bootstrap`, `verify-auth-users`, `verify-auth-routes` 실행 여부와 결과

## 후속 분류

- 미분류 P0~P1 후속 이슈: 없음. 이번 항목의 수동 UI evidence drift 위험은
  `verify-v160-manual-ui-release-checklist-closure`, `verify-manual-ui-evidence`,
  `verify-docs-ui-assets`로 닫습니다.
- V160-P2-01 Public docs consistency polish와 V160-P2-02 Tracker benchmark harness
  planning only는 같은 v1.6.0 안정화 페이즈의 별도 항목이므로 이 문서에서 구현
  완료로 판정하지 않습니다.
- V160-P2-02 Tracker benchmark harness planning only는 이 manual UI checklist closure
  항목에서 완료로 판정하지 않습니다.
- 별도 Phase 후보는 이 manual UI checklist 항목의 즉시 구현 후속으로 끌어오지
  않습니다.
