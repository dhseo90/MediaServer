# v1.6.0 Stability Verification Gates

이 문서는 V160-P0-02 `Stability verification gate cleanup`의 기준입니다.
목표는 현재 기능 기준 smoke 묶음과 flaky/attached/longrun/external gate를 분리해,
실패하거나 실행하지 않은 항목이 release pass처럼 보이지 않게 하는 것입니다.

## Gate 분류

| Gate | 기본 성격 | 대표 명령 | release evidence 기록 |
| --- | --- | --- | --- |
| Static/docs gate | 서버 실행 없이 문서, command inventory, release metadata drift를 점검 | `./server.sh verify-script-inventory`, `./server.sh verify-code-comments`, `./server.sh verify-release-metadata`, `./server.sh verify-docs-links` | 실행한 명령만 PASS/FAIL |

## Stability 기록 규칙

- `verify-script-inventory`는 documented command와 dispatch script가 일치하는지 확인하는
  static gate입니다.
- 주요 smoke suite는 실행 대상과 환경을 함께 기록합니다. attached UI smoke는 서버
  URL과 screenshot 실행 여부를 남깁니다.
- flaky verifier는 `verify-flaky-verifiers`와 `verify-fixture-cleanup-contracts`로
  cleanup failure, route wait, clipboard fallback, browser/CDP 환경 문제를 제품 회귀와
  분리합니다.
- `verify-predev`, 30분/120분 longrun, 실장비 field smoke, 외부 credential 검증은
  명시 요청 없이 실행하지 않습니다.
- 실패한 명령은 release pass에 포함하지 않습니다. 재실행해 통과한 경우에도 첫 실패
  명령과 수정/재실행 사실을 evidence에 남깁니다.
- Event POST, WebRTC DataChannel, SSE/WS metadata schema, RTSP/WebRTC media path는
  이 gate cleanup에서 변경하지 않습니다.

## `verify-predev` 건너뜀 판정

`verify-predev` summary의 `skip` 값은 단독으로 PASS/FAIL을 결정하지 않습니다.
release evidence에는 skip count와 각 skipped step의 reason을 함께 남깁니다.

- PASS 가능: `fail=0`이고 skipped step이 사용자가 요청하지 않은 선택 gate임이
  report에 명시된 경우. 예: `external-turn-hard-gate`가
  `--include-external-turn not requested`로 건너뜀.
- HOLD 또는 NOT RUN: 사용자가 요청한 hard gate, RC 필수 gate, 또는 이번 변경 범위의
  필수 검증이 환경/명령/fixture 문제로 실행되지 않은 경우.
- FAIL: skipped reason이 cleanup failure, port cleanup failure, command missing,
  schema/media path 미검증 같은 중단 조건을 숨기는 경우.
- `--skip-build`, `--soak-minutes 0`, `--skip-redaction`처럼 사용자가 명시한 축소
  옵션은 release PASS가 아니라 축소 실행 evidence로 기록합니다.

따라서 `verify-predev --soak-minutes 120`에서 `pass>0`, `fail=0`, `skip=1`이더라도
그 1건이 optional external TURN 미요청 같은 선택 gate인지 report에서 확인해야 합니다.
선택 gate 미요청으로 확인된 경우에만 "장기 predev 자체는 통과, 외부 TURN은 NOT RUN"으로
분리해 기록합니다.

## 미사용/중복 verifier 처리 원칙

- documented command가 `server.sh` dispatch table에 없으면 `verify-script-inventory`가
  실패해야 합니다.
- dispatch target script가 없거나 executable이 아니면 release gate에서 실패로 봅니다.
- 동일 목적의 verifier가 있더라도 다른 환경을 요구하면 한 결과로 합치지 않습니다.
  예를 들어 `verify-ops-client-ui`와 `verify-ops-client-ui --screenshots`는 실행
  evidence를 분리합니다.
- removed UI route(`/lab`, `/lab/rules`, `/lab/import`, `/webrtc/test`) 재개방 여부는
  client/ops UI smoke에서 확인하며, 실패를 문서 통과로 덮지 않습니다.

## 후속 분류

- 미분류 P0~P1 후속 이슈: 없음. 이번 항목에서 발견한 stability gate drift 위험은
  gate 분류 문서와 `verify-v160-stability-verification-gate`로 닫습니다.
- V160-P0-03과 V160-P0-04는 같은 P0 안정화 페이즈의 별도 항목이므로 이 작업에서
  구현 완료로 판정하지 않습니다.
- V160-P1-01~V160-P1-04, V160-P2-01~V160-P2-02, 별도 Phase 후보는 이 gate cleanup의
  즉시 구현 후속으로 끌어오지 않습니다.
