# v1.6.0 Tracker Benchmark Harness Planning

이 문서는 V160-P2-02 `Tracker benchmark harness planning only`의 기준입니다.
목표는 실제 OC-SORT adapter나 새 runtime tracker를 구현하지 않고, 별도 기능 개발 Phase에서
별도 benchmark를 열 때 필요한 harness 요구사항과 비승격 경계를 고정하는 것입니다.

## Planning-only 경계

- `analysis.trackingPolicy.tracker` 허용값은 `none`, `lite`, `kalman-lite`,
  `bytetrack`에 머뭅니다.
- `/ops/rules` tracker selector, rule validation, `AnalysisProfile`,
  `ObjectTrackerKind`, `verify-tracker-stability`, `compare-close-object-tracker`에
  OC-SORT, BoT-SORT, DeepSORT runtime tracker 선택값을 추가하지 않습니다.
- `compare-close-object-tracker --experimental-sandbox oc-sort`는 metadata-only
  sandbox manifest를 남길 수 있지만 tracker stability 실행 인자로 전달하지 않습니다.
- metadata-only sandbox manifest는 report/history용 planning artifact입니다.
- benchmark planning은 Event POST/WebRTC DataChannel/SSE/WS metadata schema 변경이나
  RTSP/WebRTC media path 변경의 근거가 아닙니다.
- tracker/Re-ID default-on, product default tracker 변경, model/runtime bundle 포함
  결정을 이 항목에서 내리지 않습니다.

## 향후 Harness 요구사항

별도 Phase에서 benchmark가 열릴 때는 아래 evidence를 먼저 갖춰야 합니다.

| 영역 | 요구사항 |
| --- | --- |
| Fixture set | close-object, field-driving, field sample candidate를 provenance와 함께 분리 |
| Candidate policy | runtime tracker 후보와 metadata-only sandbox 후보를 명확히 분리 |
| Metrics | continuity, ID switch, dropped/retained warnings, event drift, defaultOnDecision |
| Product decision | `matrix-ok`와 product default-on/default tracker 변경 판단 분리 |
| Privacy | Re-ID/crop/embedding/model path/checksum/provenance 비노출 review |
| Bundle | runtime/model bundle RC policy와 source-offer 검토 분리 |
| Reporting | summary/report/history index만 보존하고 raw media/source/auth material은 보존 금지 |

## 후속 분류

- 미분류 P0~P1 후속 이슈: 없음. 이번 항목의 benchmark planning drift 위험은
  `verify-v160-tracker-benchmark-harness-planning`, `verify-oc-sort-benchmark-boundary`,
  `verify-bot-sort-deepsort-research-boundary`로 닫습니다.
- 실제 OC-SORT algorithm adapter, BoT-SORT/DeepSORT adapter, dataset benchmark report,
  tracker replacement product review는 별도 Phase 후보입니다.
- 별도 Phase 후보는 이 planning-only 항목의 즉시 구현 후속으로 끌어오지 않습니다.
